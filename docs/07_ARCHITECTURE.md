# 07. Архитектура Unity-проекта

## Настройки проекта

| Параметр | Значение |
|---|---|
| Unity | Актуальная LTS (зафиксировать в `ProjectVersion.txt`) |
| Render Pipeline | URP, мобильный профиль |
| Input | New Input System |
| Scripting backend | IL2CPP, ARM64 |
| Min API | 26 (Android 8.0), уточняется |
| Color space | Linear |
| Контроль версий | Git + Git LFS для бинарных ассетов |

## Структура папок

```
Assets/
├── _Project/
│   ├── Scripts/
│   │   ├── Core/          (Services, события, пулы, утилиты)
│   │   ├── Player/        (контроллер, камера, ввод, фонарик)
│   │   ├── Noise/         (NoiseSystem, NoiseEvent, SurfaceType)
│   │   ├── Audio/         (AudioService, пул источников, окклюзия)
│   │   ├── Enemies/       (FSM, состояния, восприятие)
│   │   ├── World/         (Room, Socket, генератор, валидатор)
│   │   ├── Loot/          (предметы, спавн, инвентарь)
│   │   ├── Run/           (RunManager, эвакуация, правила потерь)
│   │   ├── Progression/   (улучшения, ресурсы)
│   │   ├── Save/          (SaveService, миграции)
│   │   ├── UI/            (HUD, меню, настройки)
│   │   └── Monetization/  (после MVP)
│   ├── Config/            (ScriptableObject: предметы, враги, кривые)
│   ├── Prefabs/           (Rooms, Enemies, Items, UI)
│   ├── Scenes/            (Boot, Menu, Run, Sandbox)
│   ├── Art/ (Models, Materials, Textures)
│   ├── Audio/ (SFX, Ambient, Music, Mixer)
│   └── Tests/ (EditMode, PlayMode)
```

Каждая папка `Scripts/<Module>` — отдельная **Assembly Definition** (`DarkDepths.<Module>`). Зависимости только вниз: `Core` не зависит ни от чего; `UI` может зависеть от `Run`, `Progression`; `Enemies` — от `Noise`, `Core`. Циклов нет.

## Сцены

| Сцена | Назначение |
|---|---|
| `Boot` | Инициализация сервисов → загрузка `Menu` |
| `Menu` | Главное меню, база, улучшения, настройки |
| `Run` | Вылазка, здание собирается генератором |
| `Sandbox` | Тестовая сцена для прототипов (этапы 1–4) |

## Слои (Layers) и теги

| Слой | Назначение |
|---|---|
| `Player` | Игрок |
| `Enemy` | Враги |
| `Wall` | Стены (для окклюзии звука и LOS) |
| `Interactable` | Объекты взаимодействия |
| `RoomBounds` | Триггеры границ комнат |
| `Loot` | Добыча |

Новые слои — только через отчёт агента.

## Сервисы

Единая точка доступа `Services` (статический класс-локатор): `Services.Noise`, `Services.Audio`, `Services.Save`, `Services.Run`. Регистрация в `Boot`. Интерфейсы (`INoiseService` и т. д.) для подмены в тестах. Других синглтонов нет.

## Связь между системами

- Интерфейсы: `INoiseListener`, `IInteractable`, `IDamageable`, `ISaveable`.
- События: ScriptableObject-каналы (`GameEvent`, `GameEvent<T>`) или C#-события внутри модуля.
- Система не знает о конкретной реализации других: `Enemies` зависит от `INoiseListener`, а не от `Player`.

## Конфигурация (ScriptableObject)

| Тип | Поля |
|---|---|
| `FlashlightConfig` | См. `03` |
| `EnemyDefinition` | См. `05` |
| `ItemDefinition` | id, имя, тип, вес, ценность, стек |
| `UpgradeDefinition` | id, стоимость, эффект, зависимости |
| `DifficultyCurve` | См. `06` |
| `NoiseConfig` | Громкости, множители поверхностей |
| `PaletteConfig` | Цвета |
| `RunRulesConfig` | `lossPercent`, правила первой вылазки |

Правило: баланс не живёт в коде.

## Сохранения

Два независимых блока.

**Профиль** (`profile.json`): версия схемы, ресурсы, купленные улучшения, хранилище, настройки, статистика.
**Состояние вылазки**: в памяти; на диск не пишется (D-08).

Правила:
- Формат JSON, поле `schemaVersion`; миграции `Vn → Vn+1` обязательны и покрыты тестами.
- Запись атомарная: писать в `profile.tmp`, затем заменять `profile.json`; держать `profile.bak`.
- Сохранять при: эвакуации, смерти, покупке улучшения, выходе в меню, `OnApplicationPause(true)`.
- При повреждении файла — загрузить `.bak`, иначе новый профиль + сообщение игроку.
- Запись не блокирует главный поток дольше одного кадра.

## Пулы

Универсальный `ObjectPool<T>`. Через пул: звуковые источники, снаряды/бросаемые предметы, враги, предметы добычи, визуальные эффекты, комнаты.

## Бюджеты производительности (цели)

| Параметр | Цель |
|---|---|
| FPS | 30 стабильно на низком классе, 60 на среднем |
| Realtime-свет с тенями | 1 (фонарик) + максимум 2 дополнительных рядом с игроком |
| Дальность прорисовки | 25–30 м |
| Активные враги | ≤ 4 |
| Загруженные комнаты | ≤ 8 |
| 3D-голоса одновременно | ≤ 24 |
| Draw calls | ≤ 150 |
| Время загрузки вылазки | ≤ 5 с |

Правила: static batching и baked lighting для окружения; GPU instancing для повторяющихся мешей; текстуры с атласами и сжатием ASTC; туман, постобработка, прозрачность — минимум.

Проверять FPS, нагрев, расход батареи, время загрузки на реальных устройствах начиная с этапа 1.

## Сборка Android

- Package name в формате `com.<studio>.darkdepths`.
- Build: Android App Bundle для публикации, APK для тестов.
- Keystore хранить вне репозитория, делать резервную копию.
- Сборка из CLI (`-batchmode -executeMethod`) для CI — по желанию.
