# 08. Roadmap

Формат: этап → задачи (`T<этап>.<номер>`) → критерий готовности этапа.
Задачи выполняются по порядку. Одна задача = один запрос к агенту.
Статусы отмечаются чекбоксами.

## MVP (цель первой версии)

- [ ] Одна зона (жилая), 8–12 комнат
- [ ] Вид от первого лица + фонарик
- [ ] Один враг (Слухач), реагирующий на шум
- [ ] Несколько предметов добычи
- [ ] Одно оружие
- [ ] Эвакуация
- [ ] Потеря части добычи при смерти
- [ ] 2–3 постоянных улучшения
- [ ] Сохранение профиля
- [ ] Рабочая Android-сборка

Не входит в MVP: больше одного типа врагов, несколько зон, база, реклама, покупки.

## Этап 1. Движение и свет

**Зависимости:** нет. **Документы:** 03, 07.

- [x] **T1.1** Создать проект: URP, New Input System, Android, структура папок, asmdef, `.gitignore`, сцены `Boot`/`Sandbox`.
- [x] **T1.2** Контроллер игрока от первого лица (`CharacterController`), камера, ввод через Input Actions (клавиатура + сенсор), приседание, бег.

**Готово, когда:** в комнате приятно двигаться на телефоне; фонарик помогает ориентироваться без сложной графики; сборка запускается на реальном устройстве.

## Этап 2. Визуальный прототип

**Зависимости:** этап 1. **Документы:** 02.

- [x] **T2.1** `PaletteConfig`, матовые материалы, базовое освещение сцены.
- [x] **T2.2** Модульные low-poly элементы: стена, пол, дверь, мебель (5–8 штук).
- [x] **T2.3** Силуэтный враг (модель, материал, 2–3 анимации: idle, walk, поворот головы).
- [x] **T2.4** Пост-обработка в допустимом минимуме, настройка «Снизить визуальные эффекты».

**Готово, когда:** сцена выглядит целостно, важные объекты и угрозы различимы на экране телефона при средней яркости.

## Этап 3. Звук

**Зависимости:** этап 2. **Документы:** 04.

- [x] **T3.1** `AudioService`, Audio Mixer (Master/SFX/Ambient/Music/UI), пул источников.
- [x] **T3.2** Шаги игрока по поверхностям (`SurfaceType`).
- [x] **T3.3** Фон помещения, звуки дверей и предметов.
- [x] **T3.4** 3D-позиционирование, реверберация, low-pass окклюзия.
- [x] **T3.5** Настройки громкости, визуальные подсказки звука.

**Готово, когда:** направление врага определяется на слух; при этом выживание не зависит только от звука.

## Этап 4. Первый враг и шум

**Зависимости:** этап 3. **Документы:** 04, 05.

- [x] **T4.1** `NoiseSystem`, `NoiseEvent`, `INoiseListener`, `NoiseConfig` + EditMode-тесты + Gizmos.
- [x] **T4.2** Игрок и объекты излучают шум (шаги, двери, падение предметов).
- [x] **T4.3** `EnemyDefinition`, FSM-каркас, NavMesh, состояния Patrol/Alerted/Investigate/Search/Return.
- [ ] **T4.4** Chase + Attack, урон игроку, смерть игрока.
- [ ] **T4.5** Бросаемый предмет для отвлечения.
- [ ] **T4.6** Укрытия.
- [ ] **T4.7** EditMode-тесты FSM.

**Готово, когда:** игрок понимает поведение врага, может ошибиться, исправить и выжить осмысленными действиями.

## Этап 5. Добыча и первая вылазка

**Зависимости:** этап 4. **Документы:** 01, 03, 07.

- [ ] **T5.1** `ItemDefinition`, инвентарь (список с лимитом), подбор предметов.
- [ ] **T5.2** `RunManager`: старт, эвакуация, смерть, итоговый экран.
- [ ] **T5.3** Точка эвакуации и взаимодействие.
- [ ] **T5.4** `RunRulesConfig` + правила потерь + тесты.
- [ ] **T5.5** Дубинка как оружие.

**Готово, когда:** работает цикл «вход → исследование → добыча → риск или уход → результат».

## Этап 6. Прогрессия и сохранение

**Зависимости:** этап 5. **Документы:** 01, 03, 07.

- [ ] **T6.1** `SaveService`: профиль, версия схемы, атомарная запись, `.bak`, миграции, тесты.
- [ ] **T6.2** Ресурсы и `UpgradeDefinition`.
- [ ] **T6.3** Экран улучшений (2–3 улучшения фонарика/снаряжения).
- [ ] **T6.4** Расходники: батарея, аптечка.
- [ ] **T6.5** Меню → вылазка → меню без потери данных.

**Готово, когда:** игрок понимает, зачем идти в следующую вылазку и как добыча помогает развиваться; прогресс сохраняется между запусками.

**Зависимости:** этап 6. **Документы:** 06.

- [ ] **T7.1** Компоненты `Room`, `RoomSocket`, спавн-точки.
- [ ] **T7.2** 8–12 комнат MVP по контракту.
- [ ] **T7.3** Алгоритм сборки по `seed` + выравнивание сокетов + проверка пересечений.
- [ ] **T7.4** Валидатор + EditMode-тесты (≥ 100 сидов без ошибок).

## Чек-лист качества (перед расширением контента)

- [ ] Интересно исследовать даже обычную комнату?
- [ ] Понятно, почему враг услышал шум?
- [ ] Враги различаются поведением и силуэтом?
- [ ] Есть выбор между риском и безопасностью?
- [ ] Прокачка даёт новые возможности?
- [ ] Поздняя игра не слишком проста?
- [ ] Не слишком темно?
- [ ] Пространственный звук работает на целевых устройствах?
- [ ] Стабильная производительность на Android?
- [ ] Несколько вылазок подряд ощущаются разными?

Если цикл неинтересен — не добавлять зоны и монетизацию, а улучшать то, что игрок делает каждую минуту.
