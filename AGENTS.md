# AGENTS.md — правила для ИИ-агента

Ты пишешь код Unity-проекта DARK DEPTHS. Читай этот файл первым.

## Рабочий процесс

1. Возьми **одну** задачу из `docs/08_ROADMAP.md` (ID вида `T4.2`). Не бери несколько сразу.
2. Прочитай файл темы, на который ссылается задача, и `docs/07_ARCHITECTURE.md`.
3. Реализуй только то, что описано в задаче. Не добавляй функции «заодно».
4. Проверь критерии готовности задачи.
5. В ответе дай отчёт по шаблону ниже.

Если в задаче не хватает данных — выбери значение по умолчанию из документов, укажи это в отчёте. Если данных нет и в документах — задай один конкретный вопрос.

## Шаблон отчёта

```
Задача: T<N.M> — <название>
Создано/изменено: <список файлов>
Ручные шаги в Unity Editor: <что человек должен сделать мышкой: назначить ссылки, слои, префабы>
Как проверить: <шаги + ожидаемый результат>
Допущения: <значения по умолчанию, отклонения от плана>
Не сделано: <если что-то>
```

## Правила кода

- Язык кода и комментариев: английский. Документация: русский.
- Namespace `DarkDepths.<Module>`, например `DarkDepths.Noise`. Один публичный класс на файл, имя файла = имя класса.
- Приватные поля `_camelCase`, публичные свойства `PascalCase`, константы `PascalCase`.
- Параметры баланса (скорость, радиус, урон, шансы) **не хардкодить**. Только поля ScriptableObject или `[SerializeField]`.
- Никаких `Find*`, `GetComponent` и `Camera.main` в `Update`. Кэшируй в `Awake`/`Start`.
- Никаких аллокаций в `Update`: без LINQ, `new List`, строковой конкатенации, замыканий. Используй пулы и переиспользуемые буферы (`Physics.OverlapSphereNonAlloc`).
- Объекты, которые создаются и удаляются часто (шум-маркеры, звуки, снаряды), — только через пул.
- Связь между системами: интерфейсы (`INoiseListener`, `IInteractable`) и события/каналы на ScriptableObject. Не вызывай систему напрямую через `FindObjectOfType`.
- Статических синглтонов нет, кроме `Services` (см. `docs/07_ARCHITECTURE.md`).
- Корутины допустимы для простых таймеров. Для ИИ и сохранений — явные конечные автоматы и `async` без блокировки главного потока.
- Один тип ответственности на класс. Если класс больше ~300 строк — раздели.

## Правила Unity

- **Не редактируй вручную** `.unity`, `.prefab`, `.asset`, `.meta`, если задача не требует. Пиши C#-код и перечисли ручные шаги в Editor в отчёте.
- Новые ScriptableObject-типы: `[CreateAssetMenu(menuName = "DarkDepths/<Name>")]`.
- Слои и теги: используй только перечисленные в `docs/07_ARCHITECTURE.md`. Новый слой — добавь в отчёт.
- Ввод только через New Input System. `UnityEngine.Input` не использовать.
- Код должен компилироваться без предупреждений. Не оставляй `Debug.Log` в горячих путях; для отладки — `#if UNITY_EDITOR` или `[Conditional]`.

## Тесты

Обязательны EditMode-тесты для логики без MonoBehaviour:

- расчёт радиуса и затухания шума;
- переходы состояний ИИ (на заглушках);
- валидатор генерации (нет тупиков без причины, достижимость выхода);
- сериализация и миграция сохранений;
- правила потерь при смерти/эвакуации.

PlayMode-тесты — только для критичных сценариев (вылазка от входа до эвакуации).

## Запрещено

- Добавлять пакеты и сторонние ассеты без явной задачи.
- Менять Project Settings без записи в отчёте.
- Реализовывать функции из более поздних этапов roadmap.
- Менять формат сохранений без версии и миграции.
- Применять реалистичные текстуры, постобработку, bloom, шейкинг камеры сверх `docs/02_VISUAL_STYLE.md`.
- Делать информацию доступной **только** через звук (см. `docs/04_NOISE_AND_AUDIO.md`).

## Definition of Done (любая задача)

- [ ] Компилируется без ошибок и предупреждений.
- [ ] Критерии готовности задачи из roadmap выполнены.
- [ ] Нет хардкода баланса.
- [ ] Нет аллокаций в `Update`.
- [ ] Тесты добавлены, если есть чистая логика.
- [ ] Отчёт по шаблону приложен.
